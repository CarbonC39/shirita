# Shirita 当前开发方向

> 状态：当前有效。本文用于约束近期开发范围。

## 当前问题

Shirita 已经完成了从基础存储到聊天、Prompt tree、状态、导入导出、桌面套壳和 Web 部署的一轮功能建设，但当前实现承担了过多兼容语义和 UI 特例。继续追加功能会进一步提高修改成本。

近期工作的目标不是冲刺 1.0，也不是重做所有核心抽象，而是先降低维护负担并恢复聊天主路径的可靠性。

## 已确定的方向

- Shirita 不再以 SillyTavern alternative 为产品定位。
- Tauri 桌面端与自托管 Web 端同等重要，共享 core、HTTP API 和前端。
- 从主应用移除 SillyTavern 卡片、预设、World Info、TavernHelper 等兼容层。
- 保留具有独立价值的通用能力，包括消息分支、关键词触发和正则文本转换。
- 默认 UI 将重写，目标是简单、移动端可用、方便维护，并尽量扩大消息与输入区域。
- Token 统计与 context budget 可见性继续保留。
- 状态与数值未来倾向通过规范注册的 tool 表达，但不在当前文档阶段实施。
- Prompt 的积木式组合思路继续保留；Prompt 组装大修改为明确待办，当前不设计新模式。

## 近期阶段

### 0. 文档与边界

- 更新 README、产品定位和当前文档索引。
- 将旧 milestone specs/plans 归档，避免其与当前方向混淆。
- 记录 ST 兼容删除边界、UI 重写边界和聊天运行时必须保持的不变量。
- 文档必须区分“当前已经实现”和“已经决定但尚未实现”。

### 1. 必要的体验与正确性修复

UI 重写前只处理会持续妨碍使用或可能造成错误理解的缺陷：

1. 生成结束后滚动位置异常。
2. 加载失败或生成失败后缺少可靠的重试/重置路径。
3. 隐藏一条消息会使此前消息从活动路径消失。
4. 最终请求未充分保证最新用户互动处于明确、靠后的语义位置。

以下问题并入 UI 重写，不单独堆叠临时样式修补：

- 手机顶部菜单占用过多空间。
- 移动端消息菜单受 content 宽度限制，无法合理贴近屏幕操作区。
- Composer 控件过松，文本输入区域不足。

### 2. 移除 ST 兼容层 — 已完成

- 已删除主应用中的 ST card、preset、World Info 和 TavernHelper 导入路径。
- 已删除 `st_raw` 等只为往返兼容保留的数据（迁移 0023–0024）。
- 已删除进入运行时的 ST 专用语义（depth-insert / Author's Note）。
- 保留 Shirita 原生 JSON/ZIP bundle；`/api/import` 仅接受三种显式原生格式。
- 是否提供一次性独立转换器，留到删除范围明确后决定。

### 3. 默认 UI 重写 — 已完成

- 已重建 AppShell、ChatView、MessageList 和 Composer 的布局边界。
- 聊天页使用单一、明确的消息滚动容器（MessageList 是唯一 transcript 滚动所有者）。
- 移动端使用紧凑单行导航和 viewport 级消息操作面板；会话信息（Panel/变量）移入抽屉。
- Token 信息保留，且不再通过空白占位压缩输入框。
- 状态、Panel 和次要信息不再永久侵占聊天主区域。
- 自定义 CSS 是扩展能力，文档化的语义 hook 是唯一兼容表面，内部 Tailwind 类不是兼容 API。

### 4. 后续核心规范化

在以上工作稳定后，再讨论结构化 provider 事件、tool 注册、状态更新和相关持久化。Prompt composition 的重构不与当前阶段捆绑。

## 明确保留的能力

### 正则文本转换

正则是简单、透明、与模型供应商无关的输入输出规整方式，例如过滤重复句式或模型习惯用语。它不因 ST 兼容层移除而删除。

后续整理应关注作用阶段、执行顺序、原文/Prompt/展示文本的关系以及可测试性，而不是移除能力本身。

### Token 可观测性

Token 估算、真实 usage、context window、输出预留和裁剪结果是 Agent runtime 的必要信息。当前 UI 可以调整呈现位置，但不应删除这些数据和能力。

### Prompt 积木

可组合 Prompt 仍是 Shirita 的重要思路。由于当前更紧迫的问题是聊天正确性、兼容负担和默认 UI，近期不启动 Prompt 组装大修。

## 开发约束

- 新功能默认暂停，除非它直接解除当前阶段的阻塞。
- 修复应优先建立清晰的数据语义，避免只在 UI 隐藏后端问题。
- 删除兼容代码时必须保留原生数据的可访问性，并明确迁移影响。
- 不因 UI 即将重写而推迟数据丢失、错误恢复或请求正确性问题。
- 不把历史归档文档中的任务状态视为当前承诺。
